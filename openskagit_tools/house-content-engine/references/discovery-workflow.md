# Content Discovery Workflow

## Goal

Produce a ranked backlog of **researchable investigations**, not a list of predetermined conclusions or clickbait titles.

## 1. Determine scope

Establish audience, geography, requested count, topic constraints, and whether the user wants evergreen, current, or mixed ideas.

Default: Washington homeowners; local county data may be used as the analytical laboratory.

## 2. Inspect available capabilities

Build an internal capability map for sales, assessments, land, improvements, permits, neighborhood/geography, tax, zoning/utilities, mapping, and other relevant fields.

Do not hardcode one property-data toolset.

## 3. Scan homeowner concerns

For current discovery, search recent Washington homeowner discussions plus official assessor/DOR/BTA/Commerce material.

Extract recurring concerns and assumptions rather than treating anecdotes as evidence.

## 4. Generate more candidates than requested

Suggested internal targets:

- request 10 → generate 30–40
- request 25 → 60–80
- request 50 → 100–150
- request 100 → 200–300

Generate conceptual diversity, not title variations.

## 5. Candidate record

Each candidate should contain:

- question
- homeowner concern
- hypothesis
- alternative hypothesis where useful
- primary variables
- control variables
- geography
- required data
- likely method
- possible visual
- evergreen/current classification

No final reveal yet.

## 6. Reject weak candidates

Reject definition-only topics, obvious-answer questions, unavailable-data questions, tiny/unusable samples, duplicates, privacy-centered stories, predetermined conclusions, and questions that require unsupported causal claims.

## 7. Lightweight feasibility check

Use cheap counts/distributions/metadata checks only.

Examples:

- acreage question → sale count + acreage distribution + availability of house/location controls
- shop question → reliable shop identification + group counts + sales availability
- assessment question → multiple years + neighborhood identifiers + usable parcel count

Goal: **Can we realistically test this?**

Do not conduct the full analysis during Discovery.

## 8. Score

Use the Discovery Guide seven-factor score and explicit penalties.

## 9. Diversity + novelty pass

Merge superficial duplicates and compare against prior episodes/backlog when available. New geography alone is not sufficient novelty.

## 10. Select

Return the strongest candidates. Do not force category balance at the expense of quality.

For each selected investigation provide:

- question
- why homeowners care
- why it may be revealing
- evidence/data available
- proposed investigation approach
- potential visual
- score
- research confidence: high / medium / exploratory

Do not provide the answer.

## 11. Automatic topic selection

If the user asks the skill to choose the next episode:

1. run Discovery
2. identify Tier A candidates
3. check novelty
4. prefer strong evidence availability
5. prefer an uncertain answer
6. select one
7. move into Research

Do not ask the user to choose between equivalent candidates.

## 12. Research handoff

Pass:

- question
- homeowner concern
- hypothesis
- alternative hypothesis
- geography
- target population
- variables
- controls
- available tools/capabilities
- proposed method
- required authoritative context
- potential visuals
- evidence risks
- discovery score

Research may reject the investigation.

## 13. Preserve failed candidates

If an idea fails because of unavailable data, sample limitations, or weak evidence, preserve the reason so future Discovery does not repeatedly spend effort on it.
