# Story Development & Script Workflow

## Goal

Turn verified research into an understandable, compelling homeowner story without changing the evidence.

Preferred transformation:

**verified finding → tension → reveal → explanation → practical meaning**

## 1. Story gate

Confirm homeowner relevance, a clear takeaway, sufficient evidence, visual potential, and novelty. If valid research has no worthwhile story, return to Discovery.

## 2. Central reveal

Choose one primary supported finding. Do not cram unrelated findings into one episode.

## 3. Homeowner question + promise

Translate the technical question into ordinary language and state what the viewer will understand by the end.

## 4. Narrative arc

Default:

**HOOK → SETUP → EVIDENCE → REVEAL → EXPLANATION → PRACTICAL MEANING → CLOSE**

Compress for short-form.

## 5. Hooks

Prefer:

- counterintuitive relationship
- direct question
- comparison
- assumption challenge
- original-data reveal

Avoid generic “Did you know?” / “Today we’ll talk about...” openings.

Generate about three hook variants, score for clarity/curiosity/accuracy/relevance, then choose one.

The hook may be compelling but may not exceed the evidence.

## 6. Evidence presentation

Give enough methodology for credibility, not an academic lecture. Use only the few numbers necessary to reveal the pattern; supporting detail belongs in visuals/source notes.

## 7. Fact-ledger enforcement

Every factual script sentence must map to an approved ledger entry. If it does not, verify/add it or remove it.

Distinguish observation from interpretation and preserve uncertainty language.

## 8. Practical meaning

Every episode should answer “so what?” without over-prescribing individual financial decisions.

## 9. Long-form

Use roughly 4–8 minutes when complexity warrants it. Never stretch a one-minute insight merely to create long-form inventory.

## 10. Short-form

Typical 45–90 seconds. One question, one finding, one explanation, one takeaway.

When editorially natural, a 60+ second vertical version may be useful, but do not pad.

## 11. Derivatives

One investigation may yield 1–3 distinct shorts if each has a genuinely different reveal. Do not create wording variants as separate pieces.

Develop a platform-neutral master story first, then adapt packaging.

## 12. Visual beats

Map each major narrative beat to evidence-bearing visuals:

- map
- property card/anonymized example
- comparison graphic
- infographic/chart

Prefer showing evidence while explaining it over generic footage.

Every data-bearing visual must use approved fact-ledger values.

## 13. Public examples

Anonymize specific properties where practical. Avoid owner names, parcel IDs, and unnecessary exact addresses.

## 14. Narration writing

Write for speech:

- clear relatively short sentences
- minimal jargon
- natural transitions
- deliberate number phrasing

Preserve source value, display text, and spoken/narration text separately when useful.

## 15. Script fact map

Maintain an internal mapping from script lines/claims to fact IDs. Public output does not show these annotations.

## 16. Storyboard

Each scene should contain:

- narrative purpose
- narration segment
- visual type/content
- overlay text if any
- evidence IDs
- estimated duration

Do not encode renderer-specific transformation syntax here.

## 17. Titles/thumbnails

Create after the result is known. Favor clear question/reveal, no fake drama, and one visual thesis for thumbnails.

## 18. Static/social derivatives

When useful, create a one-finding graphic or a carousel structured as question → assumption → evidence → reveal → takeaway.

Captions may extend the story but cannot introduce new unsupported claims.

## 19. Source package

Preserve authoritative references, methodology summary, property-data source, geography/time scope, and limitations for descriptions/site/archive.

## 20. QA before narration

Fact QA:

- all numbers/percentages/dates/rules/geographies match ledger
- causal language is appropriate
- limitations are preserved

Narrative QA:

- one clear question
- hook matches actual story
- evidence answers question
- reveal is clear
- takeaway resolves the opening
- minimal repetition/jargon

Visual QA:

- all required visuals defined
- data values correct
- aspect-specific layouts readable
- privacy rules honored

## 21. Narration

Generate only after QA. Do not let the narration provider rewrite approved text. Preserve original script, normalized/aligned transcript, timings, duration, and asset reference.

Use actual timings to refine scenes, captions, overlays, and reveals.

## 22. Production readiness

End with:

- `READY_FOR_PRODUCTION`
- `READY_WITH_LIMITATIONS`
- `NEEDS_RESEARCH`
- `RETURN_TO_DISCOVERY`

## 23. Story handoff

Pass:

- story ID
- question
- story promise
- central reveal
- selected hook
- title candidates + selected title
- master script
- short scripts
- script fact map
- visual beats
- required assets
- approved overlay text
- fact-ledger reference
- source package
- limitations
- prohibited claims
- target formats
- production status

After narration, append narration asset, duration, timing, and caption data.
